# Project documents

Read the [product brief](ongoing/PRODUCT_BRIEF.md) first, then [architecture](ongoing/ARCHITECTURE.md) and [testing](ongoing/TESTING.md) before a refactor. These describe the public package as it exists. They do not approve proposed changes.

| Document | Read when |
|---|---|
| [Product brief](ongoing/PRODUCT_BRIEF.md) | Checking purpose, audience, scope and commitments |
| [Architecture](ongoing/ARCHITECTURE.md) | Changing skill boundaries, installation, rendering or evidence capture |
| [Testing](ongoing/TESTING.md) | Running checks or assessing what evidence proves |
| [Style guide](ongoing/STYLE_GUIDE.md) | Changing document presentation |
| [Brand](ongoing/BRAND.md) | Changing public wording or claims |
| [Diagram index](ongoing/diagrams/INDEX.md) | Finding maintained flow diagrams |
| [Board](BOARD.md) | Finding future project work |
| [Documentation standard](STANDARD.md) | Maintaining this document set |
| [Lahe pairing](lahe.md) | Using optional live human review |
| [Verification scope](verification.md) | Reading historical extraction checks and limits |
| [Research credits](inspirations.md) | Tracing influences |

Feature-specific records belong in [features](features/). Audit and research output belongs in [reports](reports/). Durable lessons belong in [lessons](lessons/). Empty folders may not be present in a fresh Git checkout until they contain a record.

The [repository overview](../README.md) remains the installation and process entry point. The [repository instructions](../AGENTS.md) govern work here. The existing board is the sole task source; no parallel bulletin board is introduced.
